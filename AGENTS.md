# AGENTS.md — Kost Management

## Project Overview

Monorepo for a boarding house (kost) management app. Turborepo + Bun.

- **`apps/web`** — React 19 + TanStack Start (SSR), TanStack Router (file-based), Tailwind CSS v4, shadcn/ui, Zod v4
- **`apps/api`** — Hono on Cloudflare Workers, Drizzle ORM + PostgreSQL (Neon), better-auth

Domain language is Indonesian: `kamar` (room), `penghuni` (tenant), `pemilik` (owner), `tagihan` (bill).

---

## Build / Dev / Test Commands

Run from root with `bun` as the package manager.

```bash
# Dev (both apps in parallel)
bun run dev

# Dev (web only)
bun run dev:web

# Build all
bun run build

# Type-check all
bun run check-types

# Lint & format
bun run lint            # biome check (lint only)
bun run lint:fix        # biome check --write (lint + auto-fix)
bun run format          # biome format --write

# Tests (web app — Vitest)
cd apps/web && bun run test                     # run all tests once
cd apps/web && bun run test -- --run room-card  # run single test file by name
cd apps/web && bunx vitest watch               # watch mode

# API DB commands
cd apps/api && bun run db:push         # push schema to DB
cd apps/api && bun run db:seed         # seed the database
cd apps/api && bun run db:studio       # drizzle-kit studio
cd apps/api && bun run cf-typegen      # regenerate Cloudflare types
```

## Code Style

### Formatting (Biome enforces these — don't fight the formatter)

| Rule            | Value        |
| --------------- | ------------ |
| Quotes          | Double (`"`) |
| Semicolons      | Always       |
| Indent          | 2 spaces     |
| Line width      | 80 chars     |
| Trailing commas | All          |

### Imports

- Use `import type { ... }` for type-only imports — `verbatimModuleSyntax` is enabled in the web app.
- Biome auto-organizes imports (via `assist.actions.source.organizeImports`). Don't reorder manually; run `bun run lint:fix`.
- Path alias `@/*` maps to `./src/*` in the web app.
  ```ts
  import { cn } from "@/lib/utils";
  import type { User } from "@/lib/auth-client";
  ```

### Naming Conventions

- **Files**: kebab-case (`room-card.tsx`, `route-guards.ts`)
- **Components**: PascalCase (`RoomCard`, `ThemeProvider`)
- **Functions/variables**: camelCase
- **DB columns**: snake_case in schema, camelCase in TS (Drizzle convention)
- **Types/interfaces**: PascalCase

### Components

- Route components: inline arrow functions inside `createFileRoute` or `createRootRoute`. Can extract to named functions below if large.

  ```ts
  export const Route = createFileRoute("/_main/")({ component: HomePage });

  function HomePage() { ... }
  ```

- Leaf/exported components: named function declarations preferred.
- Use `cn()` from `@/lib/utils` for conditional Tailwind class merging.

### Error Handling & Types

- `strict: true` in both tsconfigs — no implicit `any`, `noUnusedLocals`, `noUnusedParameters`.
- Biome warns on `noExplicitAny` — avoid `any`, prefer `unknown` or proper types.
- Biome warns on `noNonNullAssertion` (`!`) — prefer optional chaining or explicit guards.
- `erasableSyntaxOnly: true` in web — don't use `enum` or parameter properties; use `type`/`const` patterns.
- Use Zod for runtime validation (form inputs, API responses).

### DB / API Patterns

- Drizzle schema in `apps/api/src/db/schema/`. Barrel export via `index.ts`.
- Export select/insert types: `typeof table.$inferSelect` / `$inferInsert`.
- Relations defined separately from table definitions.
- API routes use Hono's `app.get`/`app.post` style with typed context via `Hono<{ Bindings: Env }>`.
- The API runs on Cloudflare Workers — no Node.js APIs, use Web API standards only.

### shadcn/ui

- Components live in `apps/web/src/components/ui/`. Config is in `apps/web/components.json` (style: radix-nova, base: neutral).
- Don't manually edit shadcn-generated files; re-run the shadcn CLI to add/update.

## Testing

Vitest is installed in `apps/web` with `@testing-library/react` and jsdom. No tests exist yet.

- Co-locate tests next to source: `component.test.tsx` or `lib.test.ts`.
- Use `@testing-library/react` patterns (`render`, `screen`, `userEvent`).
- Run single file: `cd apps/web && bun run test -- --run <filename-pattern>`
- Vitest reads config from `apps/web/vite.config.ts` (no separate vitest.config).

## Key Gotchas

- `apps/web/src/routeTree.gen.ts` is auto-generated by TanStack Router — never edit it, excluded from Biome.
- `.env` and `.dev.vars` files in `apps/api` contain secrets — don't commit changes to them.
- The API runs on Cloudflare Workers — no Node.js APIs (`fs`, `path`, etc.), use Web API standards (`fetch`, `Request`, `Response`).
- `bun.lock` is the lockfile — don't use `npm` or `pnpm` for installs.
- The web app build runs `tsc -b` before `vite build` — type errors will block the build.
